**Short answer:** in 2026, text to CAD works if a language model **writes instructions that a real CAD engine runs**. It doesn't work if a model has to imagine the shape. Three routes are usable today:

1. **Text → parametric script** (OpenSCAD, CadQuery, build123d) for 3D parts.
2. **Text → 2D drawing**, with an AI agent typing commands into a CAD program such as CADCraft over MCP.
3. **Text → 3D mesh** from generative models, for visuals only.

Put every dimension in the prompt, and make the agent **measure what it drew** before you trust it. The runnable example below does exactly that.

_cadcraft.org is an independent guide, not the official site. CADCraft is the ArtCraft team's open-source CAD program ([getartcraft.com/apps/cadcraft](https://getartcraft.com/apps/cadcraft)). The example on this page was run with cadcraft-cli 0.8.0._

## The three routes, compared

| Route                      | What the model outputs                    | You get                                                              | Good at                                                                       | Reliably gets wrong                                                                  |
| -------------------------- | ----------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| Prompt → parametric script | OpenSCAD / CadQuery / build123d code      | A solid you can export as STL or STEP (STEP with CadQuery/build123d) | Brackets, enclosures, spacers, anything built from boxes, cylinders and holes | Fillet order and failing booleans, wrong axis, features that need sketch constraints |
| Prompt → 2D drawing        | CAD commands (lines, circles, dimensions) | A DXF/DWG drawing, a PDF sheet                                       | Plates, flanges, floor-plan outlines, panels, dimensioned sketches            | Which dimensions a fabricator needs; radius vs diameter; anything picked by clicking |
| Prompt → 3D mesh           | A triangle mesh (from a generative model) | GLB/OBJ for renders and games                                        | Organic shapes, concept visuals                                               | Every exact size. There are no dimensions, so you can't use it for manufacturing     |

The pattern holds across all three: the model is good at **turning explicit numbers into syntax** and bad at **deciding the numbers**. "A 120 × 80 mm plate with four 6 mm holes 10 mm from each corner" works. "A strong mounting bracket for a 2 kg motor" gives you a guess dressed up as a drawing.

## A real prompt and its real output

This is the 2D route, run end to end for this article.

**The prompt:**

> Draw a 120 × 80 mm mounting plate in millimetres. A 30 mm diameter hole in the centre. Four 6 mm diameter holes, 10 mm in from each corner. Outline on layer OUTLINE, holes on layer HOLES in red, dimensions on layer DIMS. Dimension the overall width and height and the centre hole.

**The commands the model (Claude, the model that writes this site's articles) produced:**

```text
-layer m OUTLINE c 7 OUTLINE

rectang 0,0 120,80
-layer m HOLES c 1 HOLES

circle 60,40 d 30
circle 10,10 d 6
circle 110,10 d 6
circle 110,70 d 6
circle 10,70 d 6
-layer m DIMS c 4 DIMS

dimlinear 0,0 120,0 60,-12
dimlinear 0,0 0,80 -12,40
dimdiameter 75,40 85,55
```

**What CADCraft reported back** (`query_entities` and `inspect_drawing`): five circles on HOLES, centred at (60, 40) Ø30 and at (10, 10), (110, 10), (110, 70), (10, 70) Ø6. Counts were `Circle 5, Dimension 3, Polyline 1`, on layers `OUTLINE`, `HOLES` and `DIMS`. Saved as a 23,503-byte DXF (2018 format) and a PDF.

![The generated mounting plate rendered by CADCraft: a 120 by 80 rectangle, a 30 mm centre hole with a diameter dimension, four small corner holes, and overall width and height dimensions](/imgs/blog/text-to-cad-plate.webp)

**What's wrong with it**, and it's typical: the drawing does exactly what the prompt said and no more. The **positions of the corner holes aren't dimensioned**, and their size isn't called out either. A machinist would have to measure them off the drawing. The prompt never asked for those dimensions, so the model didn't add them. Text to CAD inherits the gaps in your prompt.

## What a model will get wrong, with the evidence

These are failures we produced on purpose with CADCraft 0.8.0, so you know what to check for.

| Mistake                                    | What happens                                                                                                                                         | How to catch it                                           |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| "6 mm hole" written as `circle 10,10 6`    | CIRCLE takes a **radius** by default, so you get a 12 mm hole. `query_entities` reported `"radius":6.0`                                              | Ask for diameters with `d`, then check `2 × radius`       |
| An impossible value, e.g. `circle 60,40 0` | Refused with `Value must be positive and nonzero.`, but **CIRCLE keeps waiting** at its prompt, so the next line the model sends is read as a radius | Check the reply's `running` field; send `cancel` (Escape) |
| A command that needs picked objects        | `execute` with `fillet` and only a radius fails: ``invalid parameters for `fillet`: `h1` is required``                                               | Query handles first, then pass them                       |
| Inch vs millimetre                         | An imperial drawing reads `120` as 120 inches                                                                                                        | Start with `new_drawing {"metric": true}`                 |
| Missing manufacturing intent               | Tolerances, threads, finishes and datums aren't drawn unless asked for                                                                               | A human review; nothing automatic replaces it             |

## How CADCraft's MCP server and JSON channel fit in

CADCraft doesn't include a language model. It gives an agent **hands and eyes**: every menu item, tool and prompt is a command that can be typed or called with JSON. The MCP server exposes 12 tools in 0.8.0: `command_line`, `script`, `execute`, `list_commands`, `inspect_drawing`, `query_entities`, `render`, `find_text`, `new_drawing`, `open`, `save` and `cancel`. `render` returns a PNG the model can look at, and `save` to a `.pdf`, `.svg` or `.png` path exports.

**Connect it to an MCP client.** Install the desktop download, which includes `cadcraft-cli` (on macOS it's a separate zip on the release page). Then add it to your client. For Claude Code:

```bash
claude mcp add cadcraft -- cadcraft-cli mcp
```

For clients configured with JSON (Claude Desktop and others):

```json
{ "mcpServers": { "cadcraft": { "command": "cadcraft-cli", "args": ["mcp"] } } }
```

That runs **headless**, with no window. To watch the agent draw in the app, start the desktop app with `--control 7979` and use `"args": ["mcp", "--connect", "127.0.0.1:7979"]`.

**The minimal runnable example**, without any AI client. This Python script speaks MCP to `cadcraft-cli` directly, sends the commands above, checks the holes and saves the files. It ran as shown with cadcraft-cli 0.8.0 on its `PATH`:

```python
import json, subprocess

# The drawing steps an LLM produced from a plain-English request.
SCRIPT = """-layer m OUTLINE c 7 OUTLINE

rectang 0,0 120,80
-layer m HOLES c 1 HOLES

circle 60,40 d 30
circle 10,10 d 6
circle 110,10 d 6
circle 110,70 d 6
circle 10,70 d 6
-layer m DIMS c 4 DIMS

dimlinear 0,0 120,0 60,-12
dimlinear 0,0 0,80 -12,40
dimdiameter 75,40 85,55
"""

srv = subprocess.Popen(["cadcraft-cli", "mcp"], stdin=subprocess.PIPE,
                       stdout=subprocess.PIPE, text=True)
def rpc(i, method, params):
    srv.stdin.write(json.dumps({"jsonrpc": "2.0", "id": i, "method": method,
                                "params": params}) + "\n")
    srv.stdin.flush()
    return json.loads(srv.stdout.readline())["result"]
def tool(i, name, args):
    return rpc(i, "tools/call", {"name": name, "arguments": args})

rpc(1, "initialize", {"protocolVersion": "2025-06-18", "capabilities": {},
                      "clientInfo": {"name": "text-to-cad", "version": "0"}})
srv.stdin.write('{"jsonrpc":"2.0","method":"notifications/initialized"}\n')
tool(2, "new_drawing", {"metric": True})
tool(3, "script", {"text": SCRIPT})
holes = json.loads(tool(4, "query_entities", {"type": "Circle"})["content"][0]["text"])
for e in holes["entities"]:
    print(e["layer"], e["geometry"]["center"], "dia", 2 * e["geometry"]["radius"])
print(tool(5, "save", {"path": "plate.dxf"})["content"][0]["text"])
print(tool(6, "save", {"path": "plate.pdf"})["content"][0]["text"])
srv.stdin.close()
```

The empty line after each `-layer` command is an Enter, which ends the LAYER prompt. Swap `SCRIPT` for whatever your model writes. The `query_entities` check is the part not to skip.

**The JSON control channel** is the lower-level interface behind the bridged MCP mode. Start the desktop app with `--control 7979`. It then accepts one JSON request per line on `127.0.0.1:7979`, for example:

```json
{ "id": 1, "method": "cmdline.input", "params": { "text": "circle 0,0 5" } }
```

According to the project's control-protocol document, each reply is one JSON line with `ok`. A line that was typed but refused still returns `"ok": true` with an `error` field, so an agent must check `error`, not just `ok`. Use this channel when you're writing your own agent loop instead of using an MCP client.

## Where this leaves text to CAD

Use AI for the typing, not the deciding. Write the prompt like a drawing request to a junior drafter: every size, every position, every layer, and the dimensions you want shown. Let the agent draw, then make it prove the result with `query_entities` and `render`. You can open the DXF in the [online editor](/online) or the [desktop app](/download) to finish by hand. If someone downstream needs DWG or a PDF, [DXF vs DWG](/blog/dxf-vs-dwg) explains which to send.
